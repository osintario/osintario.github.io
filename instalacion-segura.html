Instalación segura de herramientas OSINT y de ciberseguridad

Muchas herramientas del directorio no se usan desde la web: se instalan. Son código de terceros que OSINTario revisa pero no audita línea por línea. Esta guía explica cómo instalarlas sin exponer tu equipo ni tus datos. Cada ficha del directorio con la etiqueta 🧪 lleva a su sección.

⚖️ Instalar no es tener permiso. Escanear, explotar o interceptar sistemas ajenos sin autorización es delito en la mayoría de los países. Practica en tu propio laboratorio.

7 reglas que valen para todas

  1. Usa una máquina virtualVirtualBox, VMware o UTM con Kali o Debian. Nunca instales en el equipo donde tienes tu correo, tu banco o expedientes reales.
  2. Toma un snapshot antesSi algo sale mal, vuelves al estado limpio en un minuto.
  3. Lee antes de ejecutarAbre install.sh y requirements.txt. Desconfía de «curl … | sudo bash» y de binarios sin código fuente.
  4. Descarga del origen oficialEl repositorio o sitio del autor, no un espejo ni un enlace de un comentario. Verifica el hash o la firma si se publica.
  5. Sin root salvo que haga faltaUna herramienta que busca alias no necesita sudo. Si lo pide, pregúntate por qué.
  6. Aísla la red y los datosRed en modo NAT, sin carpetas compartidas ni portapapeles con tu equipo. Usa cuentas y claves API creadas solo para investigar.
  7. Cierra el caso limpioExporta la evidencia con su hash, anota versión y fecha de la herramienta y vuelve al snapshot.

Kali Linux

La base del laboratorio: una máquina virtual con cientos de herramientas ya instaladas. Empieza por aquí. Sitio oficial ↗

# 1. descarga la imagen para VirtualBox o VMware solo desde kali.org/get-kali (Virtual Machines)
# 2. comprueba que el hash coincide con el publicado en la web
sha256sum kali-linux-*-virtualbox-amd64.7z
# 3. importa la VM, entra con kali / kali y cambia la clave
passwd
# 4. actualiza y toma un snapshot limpio
sudo apt update && sudo apt full-upgrade -y

Sherlock

Busca un alias en cientos de redes sociales. Sitio oficial ↗

pipx install sherlock-project
sherlock ALIAS

# sin instalar nada, con Docker
docker run --rm -it sherlock/sherlock ALIAS

⚠️ Un alias igual en dos redes es una hipótesis, no una identidad confirmada.

Abre y analiza capturas de tráfico de red. Sitio oficial ↗

Herramientas de riesgo analizadas

No decidimos por ti si las usas: las mostramos con lo que encontramos y con su enlace real, para que no termines en una copia falsa o en una estafa. Las analizamos en un contenedor aislado, sin instalarlas. Si decides probarlas, hazlo en una máquina virtual desechable y bajo tu responsabilidad.

⚠️ ARTEMIS

Riesgo alto: agentes de IA que atacan solos

Motor de Stanford (proyecto Trinity, Apache 2.0) que lanza varios agentes de IA en paralelo para encontrar y explotar vulnerabilidades. Se presentó en un paper de ICLR 2026 que lo comparó con pentesters humanos.

Qué encontramos (23-nov-2026)

  • El alcance (qué se puede atacar) solo se le escribe al modelo en el prompt: en el código no encontramos ningún bloqueo técnico que impida salir de ese alcance.
  • Los agentes corren con acceso a la red activado y ejecutan comandos reales de Kali.
  • Necesita claves pagas de OpenAI u OpenRouter; cada prueba consume créditos.
  • Último commit: 31-dic-2025. Es un proyecto de investigación, no un producto mantenido.

⚠️ RedRoot

Riesgo alto: framework ofensivo; el módulo del reel no es público

Framework ofensivo en Python (MIT, 2026) de Agampreet Singh con más de 30 módulos: phishing, backdoor, DoS, desautenticación Wi-Fi, inyección SQL y otros. Se hizo conocido por un reel que extrae contactos y SMS de un Android por Bluetooth.

Qué encontramos (23-nov-2026)

  • El módulo Bluetooth público (redrootbluesnarf) no extrae nada: solo muestra «MODULE LOCKED» y pide contactar al autor. Lo ejecutamos en un contenedor aislado (48 líneas, solo imprime texto): la captura es real.
  • El mensaje «Logging attempt... Done» es decorativo: el código no registra nada.
  • Según su autor, el ataque no usa ninguna falla: depende de que la víctima acepte el emparejamiento y el acceso a contactos y mensajes. La defensa es no aceptar dispositivos desconocidos.
  • El instalador instala bettercap con apt y 15 paquetes de Python sin fijar versiones.
  • Actualización 25-nov-2026: el repo ya no está disponible en GitHub (404). El análisis corresponde a la versión revisada el 23-nov.

⚠️ DarkFly-Tool

No recomendado: abandonado, ofuscado e incluye spam de SMS

Menú para Termux que promete instalar más de 500 herramientas eligiendo un número. Muy compartido en redes y blogs.

Qué encontramos (23-nov-2026)

  • Abandonado desde 2019 y escrito para Python 2, que ya no tiene soporte. Su propio README dice que en Linux no funciona.
  • El código principal está ofuscado: bytecode de Python 2 cifrado con una tabla de sustitución dentro de archivos ocultos (.module/files). No se puede revisar qué instala ni de dónde.
  • El instalador ejecuta comandos leídos de esos archivos ocultos, entre ellos «rm -rf» sobre carpetas del sistema de Termux.
  • Incluye 7 herramientas de spam de SMS que abusan de los formularios de código (OTP) de empresas de Indonesia (KFC, Telkomsel, Tokopedia, Matahari, JD.id) para bombardear un número. Usarlas contra alguien es acoso.
  • No lo instalamos ni lo ejecutamos: solo análisis estático del repositorio.

Según el tipo de herramienta

🧪 Python (pipx o entorno virtual)

Cada herramienta en su propio entorno, así sus dependencias no tocan el sistema. Nunca uses «sudo pip».

# si está publicada en PyPI
pipx install NOMBRE

# desde el repositorio
git clone https://github.com/AUTOR/REPO && cd REPO
python3 -m venv .venv && source .venv/bin/activate
cat requirements.txt        # revisa qué instala
pip install -r requirements.txt

🧪 Go (binario único)

Se compila a un solo archivo sin dependencias. Instala desde el código o baja el binario de «Releases» y compara su checksum.

go install github.com/AUTOR/REPO/cmd/NOMBRE@latest

# o binario publicado
sha256sum NOMBRE_linux_amd64.zip   # compara con checksums.txt

🧪 Docker (contenedor)

Usa la imagen oficial con una versión fija. No montes tu carpeta personal ni uses «--privileged».

docker run --rm -it -v "$PWD/salida:/data" AUTOR/IMAGEN:VERSION

# servicios con varios contenedores
docker compose up -d      # lee antes el docker-compose.yml

🧪 Solo en máquina virtual

El instalador pide sudo, toca el sistema o la herramienta es ofensiva (explotación, contraseñas, Wi-Fi). Úsala en una VM desechable y solo contra sistemas propios o con autorización escrita. Para Wi-Fi necesitas un adaptador USB conectado a la VM.

# 1. snapshot de la VM
# 2. en Kali muchas ya vienen en los repositorios oficiales
sudo apt update && sudo apt install NOMBRE

# 3. si solo hay instalador propio, léelo primero
git clone https://github.com/AUTOR/REPO && cd REPO
less install.sh

🧪 Instalador oficial

Programa de escritorio o paquete del proyecto. Descárgalo solo del sitio oficial y verifica la firma o el hash publicado.

sha256sum instalador.exe      # Linux / macOS
Get-FileHash instalador.exe    # Windows PowerShell

Esta guía es general: mejora con cada revisión. Si una herramienta necesita pasos propios, se indica en su ficha.
